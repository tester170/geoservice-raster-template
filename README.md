# Sentinel Classification – геоинформационный сервис картографирования по снимкам Sentinel-2

Сервис строит карту классов земного покрова для области интереса: безоблачный композит Sentinel-2 за выбранный период классифицируется в Google Earth Engine по каналам и спектральным индексам снимка (по выбору – по эмбеддингам AlphaEarth), а карта загружается массивом в проекции UTM частями по 256 × 256 пикселей. Сервис рассчитывает площади классов, для двух периодов – матрицу переходов и чистый прирост, а по кнопке выполняет сегментацию нейронной сетью SegFormer-B0. Сеть выполняется в ONNX Runtime, поэтому серверной части не нужны torch и transformers.

Режимы:

* **своя модель** – обученный классификатор (вариант на каналах и индексах снимка или на эмбеддингах AlphaEarth) и сеть SegFormer-B0 из `models/`;
* **обучение на лету** – случайный лес обучается по карте меток Dynamic World или ESA WorldCover внутри области интереса, точность проверяется на отложенных пространственных блоках;
* **обученная на лету** – такую модель можно скачать файлом JSON, загрузить из файла и применить к другой области.

Область интереса задаётся городом (граница из OpenStreetMap), нарисованным или загруженным полигоном либо готовым квадратом 30 × 30 км из карточки модели; периоды снимков – интервалами дат, два периода можно сравнить. Разрешение карты – «авто» по площади или от 10 до 500 м. В интерфейсе GeoJSON с кодами и названиями классов доступен для всей рассчитанной области. Если API вернул только GeoTIFF, интерфейс строит полигоны первого канала при скачивании. Параметр `MAX_VECTOR_KM2` задаёт предел площади для GeoJSON, включаемого непосредственно в ответ API.

## Устройство

| Файл или папка | Назначение |
|---|---|
| `main.py` | страница Streamlit – главный файл приложения: область интереса (город, полигон, готовый квадрат), режим, слои классов, таблицы, GeoTIFF и GeoJSON |
| `extensions.py` | собственная функция: получает карты классов массивами NumPy и возвращает таблицу и вывод |
| `client/` | клиентская часть: `interface.py` – оформление страницы и область интереса (границы из файлов GeoJSON, GeoPackage, ZIP с SHP и нарисованные фигуры); `maps.py` – карты folium и полигоны классов из GeoTIFF для GeoJSON |
| `server/` | серверная часть: `api.py` – FastAPI (`/classify`, `/train`, `/apply`, `/segment`, `/place?city=…`, `/cities`, `/health`); `raster_analysis.py` – справочник городов, композит Sentinel-2, признаки, классификация, площади, изменения, выгрузка, сегментация SegFormer-B0 в ONNX Runtime |
| `models/raster_model/` | модели сервиса: классификаторы `classifier_spectral.json` (каналы и индексы) и `classifier.json` (эмбеддинги AlphaEarth); в демонстрационных классификаторах обучающие точки записаны в описание, классификаторы третьей недели ссылаются на ассет обучающих точек, нейронная сеть `segformer/` (`model.onnx` и нормировка каналов), карточка `card.json` |

Классы, сезон, годы, признаки и готовые квадраты сервис берёт из `card.json`. Чтобы подключить другие модели, удалите папку `models/raster_model/` и распакуйте в корень репозитория архив моделей `пакет_для_сервиса.zip`: на её месте появится папка новых моделей. Затем при необходимости измените собственную функцию в `extensions.py`. Сеть в архиве модели – файл `model.onnx` (формат ONNX Runtime): серверной части не нужны torch и transformers.

Предел карты классов – 36 частей 256 × 256 пикселей, пересекающих область интереса (переменная `MAX_PARTS`): при пикселе 30 м этого хватает для квадрата 30 × 30 км при любом повороте, а в режиме «авто» для больших областей пиксель увеличивается до 60–500 м. Сегментация выполняется на процессоре серверной части; её предел – 144 фрагмента 256 × 256 пикселей (переменная `MAX_TILES`): сеть обучена на пикселе 10 м, для больших областей берётся 20, 30 или 60 м.

## Развёртывание на Streamlit Community Cloud

Сервис разворачивается одним приложением: страница Streamlit и серверная часть FastAPI работают в одном процессе, страница обращается к серверной части без сети.

1. Сделайте форк репозитория (кнопка **Fork**).
2. В [Streamlit Community Cloud](https://share.streamlit.io) создайте приложение из своего форка: ветка `main`, главный файл (**Main file path**) `main.py`, в **Advanced settings** – Python 3.12.
3. В поле **Secrets** вставьте ключ сервисного аккаунта Google Earth Engine – полное содержимое JSON-файла между тройными кавычками:

   ```toml
   EE_SERVICE_ACCOUNT = '''
   ВСТАВЬТЕ СЮДА ПОЛНОЕ СОДЕРЖИМОЕ JSON-ФАЙЛА КЛЮЧА
   '''
   ```

4. Нажмите **Deploy**. Библиотеки устанавливаются из `requirements.txt`, первый запуск занимает несколько минут.

Серверную часть можно развернуть и отдельно (например, в FastAPI Cloud): приложение – `server.api:app`, ключ и проект задаются переменными окружения `EE_SERVICE_ACCOUNT` и `EE_PROJECT`. Тогда странице задаётся секрет `API_URL` – адрес серверной части.

## Секреты

* `EE_SERVICE_ACCOUNT` – содержимое JSON-ключа сервисного аккаунта Google Earth Engine; `EE_PROJECT` – идентификатор проекта, если он отличается от проекта ключа;
* `API_URL` – адрес отдельно развёрнутой серверной части; без него серверная часть работает внутри приложения.

Сервисному аккаунту в проекте Google Cloud нужны роли «Earth Engine Resource Viewer» (чтение ассета обучающих точек из карточки модели) и «Service Usage Consumer», а сам проект должен быть зарегистрирован для работы с Earth Engine. Ассет должен находиться в том же проекте, что и сервисный аккаунт. Ключ хранится только в секретах платформы развёртывания и никогда не записывается в репозиторий.

## Локальный запуск

```bash
pip install -r requirements.txt
streamlit run main.py
```

Страница сама запускает серверную часть внутри себя. Чтобы проверить серверную часть отдельно (страница `/docs`), запустите `uvicorn server.api:app --port 8110` и задайте странице переменную окружения `API_URL=http://localhost:8110`.
